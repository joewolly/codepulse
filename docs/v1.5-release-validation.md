# CodePulse v1.5 release validation map

This living document maps the 53 release-blocking rows in section P of the
frozen [`v1.5 Concurrent Sessions specification`](v1.5-concurrent-sessions.md)
to concrete evidence. It does not replace or modify that contract. Test names
below are XCTest methods in `Tests/CodePulseTests/`.

Evidence labels: **Automated** is deterministic XCTest coverage;
**Integration smoke** exercises a controlled local tool installation;
**Packaging/release gate** exercises the exact release artifact; and
**Environment-dependent** is never reported passed when the required tool or
host capability is unavailable.

## Release-candidate gates outside section P

- Backup v3 wire shape, strict v1/v2/v3 import, machine-local omission, exact
  UUID preservation, bounds, Settings count copy, and release metadata:
  `Phase6BackupReleaseTests`.
- Transactional recovery, rollback, retention, permissions, path/symlink
  rejection, and unreadable-state preservation: `BackupRestoreTests`.
- Canonical version/build and frozen Sparkle public trust configuration:
  `ReleaseReadinessTests`.
- Exact Universal 2 app, helpers, DMG checksum/layout, ad-hoc signatures,
  Sparkle framework, packaged launch, and outside-checkout launch:
  `./script/package_release.sh`, `./script/smoke_release_launch.sh`, and the
  controlled release-candidate smoke procedure in `docs/releasing.md`.
- The generic tag workflow is inspected but not triggered during Phase 6. A
  tag is permitted only after independent review and merge to `main`.

Rows 1, 2, 6, and 34 retain environment-dependent real-tool or packaged UI
smoke evidence in addition to deterministic automated coverage. An unavailable
Codex/OpenCode installation is reported as unavailable, never as passed.
