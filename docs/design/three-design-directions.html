Three ways to redraw an app that times two kinds of worker

CodePulse already knows something most timers don't: a coding session is now two overlapping streams — the person, and the agents they've set running. The current UI stores that faithfully but presents it as a stack of cards. Below are three directions, from smallest change to largest, each drawn as a working mockup rather than described.

Reading the current design

The popover carries four modes

Idle, active, finishing, and Active Now all render into one 380 pt column, so the frame resizes as state changes and no mode gets a layout tuned to it.

MenuBar/MenuBarPopoverView.swift:16–45

Navigation lives in footer links

History, Insights, and Settings are four blue text buttons in a row, each opening a separate window. There is no persistent home for the app.

MenuBar/MenuBarPopoverView.swift:439–499

Interval states are text, not form

Waiting is the one state with real visual encoding — an orange label. Manual, agent, review-grace, and ended all read identically at a glance.

MenuBar/MenuBarPopoverView.swift:84, 208
Direction A — smallest change

Pulse

Keep the menu-bar model exactly as it is, but stop treating the popover as a form. Make it an instrument you read in under a second: the day as a ribbon, runs as single lines, one action.

The menu-bar item becomes the headline. A live 24-bar day ribbon plus today's total, so the popover is optional most of the time.
Cards collapse to rows. Each run is one line: state dot, workspace, tool, elapsed. Six runs fit where two cards did.
Width drops 380 → 320 pt and stops changing between modes — the frame stays put, only its contents swap.
Footer links become icons, freeing the baseline for the one number that matters.

Popover, 320 pt. One glanceable number, the day's shape, then runs as lines. Detail moves to hover and click-through.

What this touches

  • Replace ActiveNowRunRow's card treatment with a single-line row; drop the per-row Details/Finish link pair in favour of hover-revealed controls. Sources/CodePulse/MenuBar/MenuBarPopoverView.swift:70–119
  • New DayRibbonView reading hourly buckets — the projection logic already exists for the Insights chart. Sources/CodePulse/Insights/InsightsCalculator.swift, Insights/InsightsView.swift:556
  • Custom MenuBarExtra label rendering the ribbon as an NSImage; today it is text plus an SF Symbol.
  • PopoverFooter becomes an icon row; keep full labels as accessibility labels, which are already written. MenuBarPopoverView.swift:439–499
Effort

Low. One file plus a menu-bar image renderer. No data-model or window changes.

Gains

The app becomes usable without opening it. Density roughly triples in the same frame.

Costs

Hover-only controls are weaker for keyboard users; the ribbon needs a real text alternative for VoiceOver.

Direction B — conventional macOS

Command Deck

Stop scattering the app across a popover and three unrelated windows. Give CodePulse a real home: one sidebar window it shares with every Mac app you already know, and demote the popover to a quick-action strip.

One window, five sections. Now, Journal, Insights, Usage, and Integrations replace four blue footer links opening four separate windows.
The sidebar carries state. Live run count and a waiting badge sit next to their section, so the window is also a status display.
The popover shrinks to a strip — start, finish, today's total, open window. Everything else moves inside.
Free wins: window restoration, tabs, full-screen, unified toolbar search, and a menu bar that finally maps to something.

What this touches

  • New root NavigationSplitView scene; AppWindowCoordinator loses per-window show methods and gains a selected-section binding. Sources/CodePulse/App/
  • HistoryView, InsightsView, and the developer-integration panes of SettingsView become detail views rather than window roots — mostly a hosting change, not a rewrite. History/HistoryView.swift:1, Insights/InsightsView.swift:6, Settings/SettingsView.swift:1
  • MenuBarPopoverView loses IdleSessionView's project/type/goal form — that moves into the window's Now section, and the popover starts with defaults. MenuBarPopoverView.swift:222–266
  • Settings stays a real Settings scene for app preferences; only the data and integration panes move.
Effort

Medium. Mostly re-hosting views that already exist, plus new navigation state and a slimmer popover.

Gains

Feels like a Mac app rather than a menu-bar utility. Room to grow Usage and Integrations without more windows.

Costs

A window is heavier than a popover; you must keep the app genuinely usable when the window is closed, or you have lost the original appeal.

Direction C — biggest bet

Lanes

The data model is already intervals with states. Show that. Make a swimlane timeline the primary surface — one lane per workspace, every manual, agent, waiting, and review-grace span drawn in position — and let lists and totals hang off a selection.

Answers the question totals can't: was that agent hour overlapping your hour, or did you walk away? Overlap is visible, not computed.
Four states, four treatments. Solid teal manual, solid blue agent, hatched amber waiting, dashed outline review-grace — no legend needed after a day.
History becomes navigation. Scrub the timeline instead of scrolling a reverse-chronological list; the journal entry is the inspector.
The risk: timelines are unforgiving of sparse data. A day with one 20-minute session looks broken. Needs a graceful list fallback.

What this touches

  • New TimelineLaneProjection beside the existing projections — the interval data is already there, it needs lane grouping and pixel mapping. Sources/CodePulse/Activity/, Domain/AgentRunStateMachine.swift:1
  • ActivityTimelineView graduates from a text list inside a sheet to the app's primary drawing surface, most likely on Canvas for scroll performance. MenuBarPopoverView.swift:185–220
  • HistoryView's filter bar carries over intact as the timeline's filter model; the list becomes a fallback view for sparse ranges. History/HistoryView.swift, History/HistoryQuery.swift:1
  • Needs a real accessibility story: lanes must expose an ordered interval list to VoiceOver, and every state needs a non-colour cue — hatching and dashes above are doing that work.
Effort

High. New projection, new drawing surface, new interaction model, and an accessibility layer built alongside rather than after.

Gains

The only direction that shows the thing CodePulse uniquely knows. Hard for a generic timer to copy.

Costs

Fails ungracefully on light days and on wide date ranges. Needs the list view kept alive underneath it, not replaced.

If you only pick one

A and C are not really rivals. A is the popover, C is the window, and B is the shell that holds them — the strongest end state is B's sidebar window with C's timeline as its Now section and A's ribbon in the menu bar.

Sequenced that way, start with A. It is one file, it ships independently, and it proves whether the ribbon reads at menu-bar size before anything expensive depends on that answer. If the ribbon works, C's lanes will too.
